# LeetCode 33. Search in Rotated Sorted Array

**Difficulty:** Medium

**Category / Pattern:** Binary Search

---

## Problem Description
```
Given a sorted array that has been rotated at an unknown pivot, search for a target value.
Return its index if found; otherwise return `-1`.
The algorithm must run in **O(log n)** time.
```
---

## Example 1

**Input**

```text
nums = [4,5,6,7,0,1,2]
target = 0
```

**Output**

```text
4
```

---

## Example 2

**Input**

```text
nums = [4,5,6,7,0,1,2]
target = 3
```

**Output**

```text
-1
```

---

## Observation
```
Although the array is rotated, **one half is always sorted**.
Use Binary Search to determine which half is sorted and decide where the target can exist.
```
---

## Solution Idea
```
* Find the middle element.
* Determine whether the left half or right half is sorted.
* Check if the target lies within the sorted half.
* Continue searching in the appropriate half.
```
---

## Algorithm
```
1. Initialize `left` and `right`.
2. Find `mid`.
3. If `nums[mid]` is the target, return `mid`.
4. Check which half is sorted.
5. Search the appropriate half.
6. If not found, return `-1`.
```
---

## Pseudocode

```text
left = 0
right = last index
While left <= right
    mid = (left + right) / 2
    If nums[mid] == target
        Return mid
    If left half is sorted
        If target lies in left half
            right = mid - 1
        Else
            left = mid + 1
    Else
        If target lies in right half
            left = mid + 1
        Else
            right = mid - 1
Return -1
```

# Implementation
This algorithm is the standard approach for **Searching in a Rotated Sorted Array**. It uses a modified binary search to find the target in O(log n) time.

Here is the translation into Java, Python, and C++.

*(Note: In Java and C++, `mid` is calculated using `left + (right - left) / 2` instead of `(left + right) / 2` to prevent potential integer overflow errors on very large arrays).*

### Java

```java
class Solution {
    public int search(int[] nums, int target) {
        if (nums == null || nums.length == 0) return -1;        
        int left = 0;
        int right = nums.length - 1;        
        while (left <= right) {
            int mid = left + (right - left) / 2;            
            if (nums[mid] == target) {
                return mid;
            }            
            // If left half is sorted
            if (nums[left] <= nums[mid]) {
                // If target lies in left half
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } 
            // Else right half is sorted
            else {
                // If target lies in right half
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }        
        return -1;
    }
}
```

### Python

```python
class Solution:
    def search(self, nums: list[int], target: int) -> int:
        if not nums:
            return -1            
        left = 0
        right = len(nums) - 1        
        while left <= right:
            mid = (left + right) // 2            
            if nums[mid] == target:
                return mid                
            # If left half is sorted
            if nums[left] <= nums[mid]:
                # If target lies in left half
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            # Else right half is sorted
            else:
                # If target lies in right half
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1                    
        return -1
```

# Explanation

The pseudocode you provided is a variation of **Binary Search** specifically designed to solve the **"Search in Rotated Sorted Array"** problem.

Normally, binary search only works on perfectly sorted arrays. However, if a sorted array is rotated (e.g., `[1, 2, 3, 4, 5, 6, 7]` becomes `[4, 5, 6, 7, 1, 2, 3]`), standard binary search fails. This algorithm cleverly works around the rotation to maintain a time complexity of O(log n).

Here is the step-by-step breakdown of how and why it works:

### 1. The Setup

```text
left = 0
right = last index
While left <= right
    mid = (left + right) / 2

```

Like a standard binary search, we define our search boundaries using `left` and `right` pointers and calculate the `mid` point. We continue looping as long as our search window is valid (`left <= right`).

### 2. The Base Case

```text
    If nums[mid] == target
        Return mid

```

If we land directly on the target number, we immediately return its index.

### 3. The Core Insight: Finding the Sorted Half

The secret to this algorithm lies in one mathematical certainty: **If you split a rotated sorted array in half, at least one of the two halves will always be perfectly sorted.**

```text
    If left half is sorted

```

In code, we determine this by checking if the element at the `left` pointer is less than or equal to the element at `mid` (i.e., `nums[left] <= nums[mid]`). If it is, we know for a fact that the left half has no rotation point in it.

**If the left half IS sorted:**

```text
        If target lies in left half
            right = mid - 1
        Else
            left = mid + 1

```

Because the left half is perfectly sorted, we can easily check if our target belongs there by seeing if it falls between `nums[left]` and `nums[mid]`.

* If the target is inside this range, we throw away the right half and move our `right` pointer to `mid - 1`.
* If the target is *not* in this range, it must be in the other half, so we throw away the left half and move our `left` pointer to `mid + 1`.

### 4. Handling the Alternative

```text
    Else
        If target lies in right half
            left = mid + 1
        Else
            right = mid - 1
```

If the first condition (`If left half is sorted`) was false, then the rotation point must be in the left half. Consequently, **the right half must be the perfectly sorted half.**

We apply the exact same logic in reverse: we check if the target falls within the predictable, perfectly sorted bounds of the right half (`nums[mid] < target <= nums[right]`).

* If it does, we move `left` to search the right half.
* If it doesn't, we move `right` to search the left half.

### 5. Target Not Found

```text
Return -1

```

If the `While` loop finishes exhausting every possible valid search window (`left` becomes greater than `right`) and we never hit `nums[mid] == target`, the target does not exist in the array.
